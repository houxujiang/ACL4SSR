# Shadowrocket 导入与检查

此文件可以作为待手机验收的独立分流配置交付；它只含规则和策略组，没有节点。现有原生节点订阅继续保留。尚未在iPhone上导入、编译或连接测试。

1. 先更新Shadowrocket首页现有的节点订阅，确认原来的15个节点仍可使用。
2. 配置页点右上角“＋”，粘贴发布后的 `shadowrocket-routing.conf` 下载地址，下载配置。这个地址用于“配置”，不是首页的节点订阅地址。
3. 点下载的配置，选择“使用配置”；再进入其 `ⓘ → 代理分组` 检查成员。使用配置会编译配置并刷新远程规则集。
4. 四个组 `💬 OpenAi`、`Ⓜ️ 微软Bing`、`Ⓜ️ 微软云盘`、`Ⓜ️ 微软服务`，在仅有当前这份15节点订阅时都应有14个候选：日本1、新加坡1、美国4、韩国8。不要出现唯一的香港出口；香港入口转美国/韩国的节点应保留。
5. 检查无误后，首页“全局路由”选择“配置”，再连接。选择“代理”会跳过配置的策略分流。

这些操作依据[配置作者的导入说明](https://github.com/LOWERTOP/Shadowrocket/blob/main/README.md#L435)与[全局路由说明](https://github.com/LOWERTOP/Shadowrocket/blob/main/README.md#L341)，不同版本菜单名称可能略有区别。

## 正则如何取节点

`policy-regex-filter` 按Shadowrocket已有候选节点的**显示名称**筛选，不会访问3x-ui API、下载另一份订阅或创建新节点。xui命名按末尾出口识别：usa为美国、kr/skr为韩国、tk为日本、sg为新加坡；入口的hk/tk/sg不决定出口分类。普通中文地区名也有匹配分支。

配置没有写死私有订阅地址或手机上的订阅名称，也没有使用尚未核实的include-all-proxies参数。若装有多份订阅，其他订阅中名称匹配的节点也可能进入候选池；仅凭此文件不能保证手机上始终恰好14个候选。

若动态组为空或混入其他订阅，可在该组启用“订阅”，并在“服务器节点”中选择现有这份原生订阅，再保留其正则筛选。作者说明这种方式会把筛选范围限制到所选订阅；实际菜单及行为仍需在手机上确认。[订阅范围说明](https://github.com/LOWERTOP/Shadowrocket/blob/main/README.md#L929)

## 当前适配限制

- AI与三个微软组直接测速四区出口正则的并集，避免嵌套测速组；这保持候选集合，但测速行为仍待手机确认。
- 台湾没有出口，固定REJECT；奈飞节点组使用“节点选择”兜底。
- 未来地区组为空时的Shadowrocket回退行为未验证；组为空时先修正订阅范围，不应直接假定会拒绝或正确分流。
- 原生节点更新后名称变化可能影响匹配。更新远程配置会覆盖本地对分组订阅范围等设置的修改，更新后需重新检查。
- 此文件提供分流规则。原配置的DNS、重写、MITM及其他本地自定义项不会由此文件继承。

编译或规则集下载失败时，应保留原配置并查看错误；不要把“文件能下载”当作分流已生效。
